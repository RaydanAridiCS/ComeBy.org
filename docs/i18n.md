# Translations (i18n)

Comeby ships in English only, but every user-facing string already goes through [next-intl](https://next-intl.dev), so adding a language is mostly translation work.

## Where strings live

- `src/i18n/messages/en.json` is the message catalogue, using ICU syntax for plurals and variables.
- Components use `useTranslations()` / `getTranslations()`. Emails and background jobs use `getServerTranslator()` from `src/i18n/config.ts`.
- Validation messages in Zod schemas are **translation keys** (for example `"rsvp.nameRequired"`), translated by `useTranslateError()` in the browser and by `runAction` on the server.
- Types: `src/i18n/global.d.ts` makes keys type-checked against `en.json`.

## Adding a language

1. Copy `en.json` to `<locale>.json` (for example `ar.json`) and translate it.
2. Add the locale to `LOCALES` and `catalogs` in `src/i18n/config.ts`.
3. Choose how the locale is picked. Comeby currently uses a fixed locale so pages stay prerenderable. Options are a locale prefix (`/ar/...`) with next-intl routing, or a per-event language chosen by the host (guests see the invite in the host's language). See [ADR 0005](adr/0005-i18n-single-locale.md).
4. For right-to-left languages, set `dir="rtl"` on `<html>`. shadcn/ui was set up with RTL support (logical CSS properties).
