# Routes

Every page and route handler under `src/app`, grouped by who uses it. There is no `middleware.ts` or `proxy.ts`: each page, action and handler does its own checks.

Mutations are **server actions**, not HTTP endpoints, and are listed at the end. The route handlers below exist for things a server action can't do: file downloads, redirects, polling, and calls from other services.

## Public pages

| Path | What it is | Indexed? |
|---|---|---|
| `/` | Landing page | Yes |
| `/privacy`, `/terms` | Legal pages | Yes |
| `/<slug>` | The invite: card, countdown, RSVP form, guest list (if the host allows), calendar and map links, report button, and the guest's own data controls | No (`noindex`) |
| `/unsubscribe?t=<token>` | Confirmation page for an unsubscribe link | No |
| `/login`, `/signup`, `/forgot-password`, `/reset-password` | Host sign-in and account recovery | No |

Only `/`, `/privacy` and `/terms` are in the sitemap and allowed in `robots.txt`; the list is `INDEXABLE_PATHS` in `src/config/seo.ts`, read by both `robots.ts` and `sitemap.ts`.

An event's slug shares the top level with these pages, so `RESERVED_SLUGS` in `src/config/site.ts` lists every word a host cannot choose. **Add a word there before adding a new top-level page.**

## Public route handlers

| Method and path | Returns | Notes |
|---|---|---|
| `GET /<slug>/opengraph-image` | The 1200×630 link-preview image, in the event's theme | Generated by `next/og` |
| `GET /<slug>/calendar.ics` | The event as a calendar file | Title is prefixed `CANCELLED:` for cancelled events. 404 when hidden |
| `GET /<slug>/qr` | A 1024 px PNG QR code that opens the invite | Cached for a day. 404 when hidden |
| `GET /r/<responseId>.<secret>` | Redirect to the invite | Checks the guest's edit credential, sets the cookie for that event, then redirects. An invalid link redirects to `/` |
| `GET /api/rsvp/export?event=<eventId>` | The guest's own response as a JSON file | See below |
| `GET /api/unsubscribe?t=<token>` | Redirect to `/unsubscribe` | For people who open the one-click URL in a browser |
| `POST /api/unsubscribe?t=<token>` | 200, or 400 for a bad token | One-click unsubscribe for mail apps (RFC 8058) |
| `GET /uploads/<key>` | A cover image | Only when `STORAGE_PROVIDER=local`; 404 otherwise |
| `GET /manifest.webmanifest`, `/robots.txt`, `/sitemap.xml` | Generated by `manifest.ts`, `robots.ts`, `sitemap.ts` | |

### `GET /api/rsvp/export`

The guest is identified by the edit-credential cookie for that event; there is no other authentication.

- `200`: a JSON attachment named `<event-title>-my-response.json`:
  ```json
  {
    "event": { "title": "...", "startsAt": "ISO date", "timezone": "Asia/Beirut" },
    "response": {
      "status": "going", "name": "...", "phone": null, "email": null, "message": null,
      "plusOnes": 0,
      "answers": [{ "question": "...", "answer": "..." }],
      "submittedAt": "ISO date", "updatedAt": "ISO date"
    }
  }
  ```
- `404 {"error":"not_found"}`: no valid credential for that event, or a malformed id.
- `429 {"error":"rate_limited"}`: more than 10 download or delete requests for this response in an hour.

## Host area (signed in)

| Path | What it is |
|---|---|
| `/dashboard` | The host's events, upcoming and past |
| `/dashboard/events/new` | Create an event. `?theme=<id>` preselects a theme |
| `/dashboard/events/<id>` | The event dashboard: counts, responses, activity, sharing, nudge |
| `/dashboard/events/<id>/edit` | Edit an event |
| `/dashboard/settings` | Profile, password, email alerts, push, sessions, data download, account deletion |

| Method and path | Returns | Notes |
|---|---|---|
| `GET /api/events/<id>/live` | The dashboard's data as JSON | Polled by the event dashboard every 15 seconds. `401` signed out, `403` not the host, `404` unknown |
| `GET /api/events/<id>/export` | Every response as a CSV file | See below |
| `GET /api/account/export` | Everything about the host's account as a JSON file | See below |
| `* /api/auth/*` | Better Auth's own endpoints | Sign-in, sign-up, sessions, password and email changes, the Google callback |

### `GET /api/events/<id>/export`

A UTF-8 CSV with a byte-order mark (so Excel reads accents and emoji), named `<event-title>-responses.csv`. Columns: guest, response, +1, phone, email, message, one column per custom question, submitted, updated. Cells that would be read as a formula are prefixed with an apostrophe. `401`, `403` and `404` as above.

### `GET /api/account/export`

A JSON attachment named `comeby-my-data.json` with `exportedAt`, `profile`, `settings` and `events`; each event includes its details, pasted invitee addresses and every response. Built on request and never stored. `401` when signed out; `429` after 5 downloads in a day.

## Called by other services

| Method and path | Caller | Notes |
|---|---|---|
| `GET /api/health` | Docker, Coolify, uptime monitors | `200 {"status":"ok"}` when the database answers, `503` otherwise |
| `POST /api/client-error` | The app's own error boundaries, in the browser | Forwards a browser error to error reporting. Body: `{ name, message, stack?, digest?, route? }`, at most 10 KB. `204` on success or when reporting is off, `429` after 20 an hour per network |
| `POST /api/email/webhook/resend` | Resend | Bounces and complaints. Verified with the Svix signature headers |
| `POST /api/email/webhook/generic` | Any other mail provider, or a script | `Authorization: Bearer <EMAIL_WEBHOOK_SECRET>` and `{ "type": "bounced" \| "complained", "email": "..." }` |

Both webhooks answer `404` when their secret isn't configured, `401` for a bad signature or secret, `413` for a body over 100 KB, and `200` otherwise, including for events they ignore. Details in [email.md](email.md#bounce-and-complaint-webhooks).

## Error pages

`src/app/not-found.tsx`, `error.tsx` and `global-error.tsx` at the root cover the whole app. No route segment has its own.

## Server actions

Each lives in `src/features/<feature>/actions.ts`, is wrapped in `runAction`, validates its input with Zod and returns an `ActionResult`.

| Feature | Actions | Who |
|---|---|---|
| `events` | create, update, cancel, close or reopen RSVPs, send the nudge, duplicate, delete, upload cover, remove cover, remove a response | Host |
| `rsvp` | submit a response, delete my response, report an event | Anyone with the link |
| `settings` | update alert settings, save or remove a push subscription, revoke one session, revoke all other sessions | Host |
| `admin` | restore an event, delete an event | Operator |
| `unsubscribe` | confirm an unsubscribe | Anyone with a valid token |

Sign-in, sign-up, password and email changes and account deletion go through the Better Auth client, not through actions in this list.
